## 3. 通过执行器执行 IK 结果

文件：`examples/day11/ik_joint_tracking_probe.py`

控制场景的仿真步长为：

```text
timestep = 0.002 s
physics frequency = 500 Hz
```

使用：

```text
CONTROL_EVERY = 10
```

表示每 10 个物理步更新一次目标，控制频率为：

```text
500 / 10 = 50 Hz
```

关节轨迹持续 100 个控制拍，即 2 秒；随后保持最终目标 500 个物理步，即 1 秒。总仿真时间为 3 秒。

动力学执行使用：

```python
command_arm_joint_positions(scene, target)
mujoco.mj_step(scene.model, scene.data)
```

`command_arm_joint_positions()` 只修改 `ctrl`。实际的 `qpos` 和 `qvel` 由 `mj_step()` 根据执行器、惯性、重力和其他物理作用计算。

## 5. 为什么位置执行器会有稳态误差

当前 Panda 关节执行器可以近似理解为 PD 位置控制器：

```text
actuator torque ≈ Kp * (ctrl - qpos) - Kd * qvel
```

以 joint2 为例：

```text
ctrl - qpos
= 0.083667054 - 0.090743771
= -0.007076717 rad
```

joint2 的位置增益约为 `4500`，因此静态力矩约为：

```text
4500 * (-0.007076717) ≈ -31.8 N·m
```

这与该姿态下 joint2 的 `qfrc_bias ≈ -31.51 N·m` 接近。也就是说，执行器需要保留一定位置误差，才能产生抵抗重力负载的静态力矩。

因此：

```text
IK目标准确
不等于
动力学执行后实际位置必然同样准确
```

## 6. MuJoCo 状态和力的含义

| 变量 | 含义 | Panda 手臂中的单位 |
|---|---|---|
| `qpos` | 实际关节位置 | rad |
| `qvel` | 实际关节速度 | rad/s |
| `ctrl` | 位置执行器的目标角度 | rad |
| `qfrc_actuator` | 执行器产生的广义力 | N·m |
| `qfrc_bias` | 重力、科里奥利力和离心力等偏置力 | N·m |
| `qfrc_applied` | 用户额外施加的广义力 | N·m |

对于旋转关节，广义力就是关节力矩。

## 7. 理想偏置力补偿

文件：`examples/day11/bias_compensation_probe.py`

机械臂动力学可以简化写为：

```text
M(q) qacc + b(q, qvel)
= actuator torque + applied torque
```

其中 `qfrc_bias` 对应 `b(q, qvel)`。

补偿策略为：

```python
scene.data.qfrc_applied[:7] = (
    scene.data.qfrc_bias[:7]
)
```

即将 MuJoCo 当前计算的偏置力作为额外前馈力施加，从而抵消等式左侧的偏置项。

由于 `qfrc_bias` 依赖当前 `qpos` 和 `qvel`，补偿必须在每个 `mj_step()` 前更新，不能只在运动开始时计算一次。

当前控制结构为：

```text
目标关节角
├── 位置反馈控制器 → 执行器力矩
└── 模型前馈补偿   → 偏置补偿力矩
```

## 8. 补偿实验结果

最终偏置力与施加的补偿几乎一致。例如：

```text
joint2 bias:    -31.510297885 N·m
joint2 applied: -31.510297801 N·m

joint4 bias:    +21.480956134 N·m
joint4 applied: +21.480956153 N·m
```

补偿后的最大关节误差：

```text
2.456302e-07 rad
```

补偿后的末端位置误差：

```text
2.092922e-05 m
```

即约 `0.0209 mm`，已经接近 Day 10 的 IK 求解误差。

对比结果：

| 指标 | 无补偿 | 有补偿 |
|---|---:|---:|
| 最大关节误差 | `7.08e-03 rad` | `2.46e-07 rad` |
| 末端位置误差 | `9.95 mm` | `0.0209 mm` |
| 最终速度范数 | `3.17e-06 rad/s` | `3.08e-06 rad/s` |

这一对照说明主要误差来自动力学负载下的位置伺服稳态误差，而不是 IK 计算错误。

## 9. 为什么称为理想补偿

MuJoCo 使用同一套精确模型产生动力学并计算 `qfrc_bias`，所以补偿几乎可以完全抵消模型中的偏置力。

真实机器人通常存在：

- 质量和质心估计误差；
- 未知末端负载；
- 摩擦和传动间隙；
- 传感器噪声；
- 通信和计算延迟。

因此真实机器人的模型补偿不会像本实验一样完美。后续也可以替换为纯位置控制、重力补偿、PID、计算力矩控制或笛卡尔阻抗控制。目前使用理想补偿，是为了建立一个容易分析的基线并隔离误差来源。

## 10. 正式手臂控制接口

文件：`src/panda_mujoco/arm_control.py`

建立了两个接口：

```python
command_arm_joint_positions(scene, target_positions)
```

负责：

- 检查目标形状为 `(7,)`；
- 检查目标全部有限；
- 检查目标位于执行器控制范围；
- 根据执行器名称写入对应 `ctrl`。

它不会修改 `qpos`，也不会推进时间。

```python
apply_arm_bias_compensation(scene)
```

负责根据关节名称找到七个手臂自由度，并将当前 `qfrc_bias` 写入相应 `qfrc_applied`。

它同样不会调用 `mj_step()`。

职责划分为：

```text
arm_control.py
├── 检查并写入关节目标
└── 准备偏置力补偿

example control loop
├── 决定何时更新目标
├── 决定是否应用补偿
└── 调用 mj_step() 推进动力学
```

## 12. 今日必须掌握的内容

1. IK 负责求目标关节角，不负责模拟电机运动。
2. `ctrl` 是目标命令，`qpos` 是实际状态，两者不能混为一谈。
3. `mj_step()` 才会推进时间并计算动力学状态变化。
4. 位置执行器可能需要稳态位置误差来产生抗重力力矩。
5. `qfrc_bias` 表示当前状态下的动力学偏置力。
6. `qfrc_applied` 是用户额外施加的广义力。
7. 偏置力前馈补偿与位置反馈控制可以组合使用。
8. 仿真中的精确补偿只是理想基线，后续可以替换为其他控制策略。

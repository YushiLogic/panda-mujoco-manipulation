## 0. 总览：一次抓取在技术上被拆成了什么

人类伸手抓方块是一个动作，工程上它被拆成 **5 个层级**，本仓库每个层级对应独立的模块：

```
┌─ 策略层 (Policy)        脚本状态机 / 随机策略 / SAC 策略
│   pick_controller.py, reach_env.py, continuous_env.py
├─ 任务层 (Task)          抓取目标几何、接触语义、成功判定、奖励
│   grasp_task.py, contact.py, rewards.py, termination.py
├─ 规划层 (Planning)      逆运动学 IK、轨迹插值
│   ik.py, kinematics.py, motion.py, cartesian_trajectory.py
├─ 控制层 (Control)       位置伺服命令、夹爪命令、重力补偿
│   arm_control.py, gripper.py, action_mapping.py
├─ 物理层 (Physics)       MuJoCo 刚体动力学、碰撞接触、数值积分
│   simulation.py, panda.xml, scene_with_cube.xml
└──────────────────────────────────────────────────────────
```

一次完整的脚本抓取（`run_scripted_pick`，见 `pick_controller.py`）按下面的时序发生：

```
RESET → MOVE_ABOVE → APPROACH → CLOSE_GRIPPER → VERIFY_CONTACT
      → LIFT → CHECK_SUCCESS → DONE（任一步失败 → FAILED）
```

实测 seed=42 的一次运行（方块 4 cm，质量 0.064 kg）：

| 阶段 | 含义 | 实测仿真耗时 |
|---|---|---:|
| RESET | 机械臂回 home、方块随机化并自然落稳 | — |
| MOVE_ABOVE | 运动到方块正上方 10 cm 的预抓取点 | 4.520 s |
| APPROACH | 保持姿态垂直下降到抓取高度 | 2.520 s |
| CLOSE_GRIPPER | 夹爪闭合，形成持续双侧接触 | 0.192 s |
| VERIFY_CONTACT | 只读监测器，确认接触合格（不发动作） | 0 s |
| LIFT | 保持闭合，垂直抬升 8 cm | 2.520 s |
| CHECK_SUCCESS | 在高处稳定保持 0.5 s | 0.500 s |
| 结果 | 成功，方块抬升约 7.7 cm，双侧 32 个接触点 | — |

下面逐层讲原理。

# 1. 机器人本体：Panda 的机械结构与数学描述

## 1.1 7 自由度冗余臂 + 平行夹爪

Franka Emika Panda 是一台 **7 轴串联机械臂**（7 个旋转关节 joint1–joint7），末端带一个
**双指平行夹爪**（2 个平动关节 finger_joint1/2）。

串联机械臂的特点：连杆首尾相接，每个关节给末端提供一个运动自由度。Panda 的 7 个关节轴
并非全部平行或垂直正交，而是经过优化的偏置布置（见 `panda.xml` 中 link2–link7 上的
`quat="1 ±1 0 0"` 等 90° 坐标系翻转），目的是在紧凑结构内获得大工作空间和避奇异能力。

**为什么是 7 轴而不是 6 轴？** 末端在空间中的位姿只有 6 个自由度（3 个位置 + 3 个姿态）。
6 轴臂可以到达任意位姿但构型唯一；7 轴多出 1 个**冗余自由度**，使得同一末端位姿对应
无穷多组关节角，机器人可以利用这个「零空间」避障、避关节极限、优化灵巧度。本项目的
IK 求解器实测 6×7 雅可比秩为 6、零空间维数恰好为 1（见 §3.3）。

各关节的物理限位（来自 `panda.xml`，单位弧度）：

| 关节 | 运动学范围 | 执行器力矩限制 | 说明 |
|---|---|---|---|
| joint1 | ±2.8973 rad (±166°) | ±87 N·m | 底座回转 |
| joint2 | ±1.7628 rad (±101°) | ±87 N·m | 肩关节 |
| joint3 | ±2.8973 rad | ±87 N·m | 肘部上方 |
| joint4 | [−3.0718, −0.0698] | ±87 N·m | **肘弯关节，不允许过零** |
| joint5 | ±2.8973 rad | **±12 N·m** | 腕部 |
| joint6 | [−0.0175, 3.7525] | ±12 N·m | 腕部 |
| joint7 | ±2.8973 rad | ±12 N·m | 法兰盘旋转 |

注意 joint4 的范围全为负——这是 Panda 的结构约束（肘部不能翻到另一侧）。这也是
`simulation.py` 中 home 姿态必须把 joint4 设为 −1.57079（弯 90°）而不能用默认 0 的原因：
0 超出 joint4 限位，直接以默认姿态启动会产生非法状态和开机甩动。

## 1.2 自由度账本：nq=16、nv=15、nu=8 怎么来的

加载模型后实测：`nq=16, nv=15, nu=8`。这三个数是机器人学最基础的「状态会计」：

- **qpos（广义位置，16 维）**：7 个铰链关节各 1 个角度（7）＋ 2 个手指平动关节各 1 个
  行程（2）＋ 方块自由关节的 3 位置 + 4 四元数（7）＝ 16。
- **qvel（广义速度，15 维）**：7 臂 + 2 指 + 方块自由关节的 6 个速度（3 线速度 + 3 角速度）
  ＝ 15。注意四元数有 4 个数但只有 3 个旋转自由度，所以位置比速度多 1 维。
- **ctrl（控制量，8 维）**：7 个手臂电机 + 1 个夹爪电机（一个电机通过传动同时驱动两指）。

记忆要点：**铰链/平动关节占 1 个 qpos 和 1 个 qvel；自由关节占 7 个 qpos 和 6 个 qvel；
执行器数 ≠ 关节数**（夹爪 2 关节只配 1 个执行器）。

## 1.3 连杆、惯性参数与三类几何对象

`panda.xml` 中每个 `<body>` 是一个**刚体连杆**，包含：

- `<inertial>`：质量、质心位置、惯量张量（`fullinertia` 六个数 = 3 个转动惯量 + 3 个惯量积）。
  例如 link1 质量 4.97 kg。这些参数决定动力学方程中的质量矩阵 M 和重力项 g。
- `<geom>`：挂在连杆上的几何形状，分两类用途：
  - **视觉网格**（`class="visual"`，`contype=0 conaffinity=0`）：只负责渲染，不参与碰撞；
  - **碰撞网格/盒**（`class="collision"`）：参与碰撞检测。指尖用 5 个小 box 近似软垫
    （`fingertip_pad_collision_1..5`），比真实曲面网格接触更稳定、求解更快。
- `<site>`：**无质量、不碰撞的命名参考坐标系**。本项目唯一的 site 是
  `ee_center_site`，位于手掌内部，作为「末端点」被 IK 和观测读取
  （`kinematics.py` 里 `data.site("ee_center_site").xpos`）。

把视觉与碰撞几何分离是机器人仿真的标准做法：视觉网格可以几百万面追求好看，
碰撞几何尽量简单追求物理稳定与计算效率。全模型共 83 个 geom。

## 1.4 夹爪机构：腱传动、等式约束与 255 命令映射

真实 Panda 夹爪的两个手指由一个电机通过机构对中驱动。模型用两个 MuJoCo 机制还原：

```xml
<tendon>
  <fixed name="split">
    <joint joint="finger_joint1" coef="0.5"/>
    <joint joint="finger_joint2" coef="0.5"/>
  </fixed>
</tendon>
<equality>
  <joint joint1="finger_joint1" joint2="finger_joint2" .../>
</equality>
```

- **fixed tendon（固定腱）**：把一个执行器的行程按 0.5/0.5 分给两个手指关节，
  所以 1 个 `actuator8` 能同时驱动 2 个关节；
- **equality 约束**：强制两指位置始终相等（对中运动），防止单侧跑偏；
- **命令重映射**：真实 Panda 夹爪 API 用 0–255 的整数命令，而物理关节行程是 0–0.04 m。
  `actuator8` 的 `gainprm="0.015686…"` 就是换算系数（0.04 × 100 / 255），
  让 ctrl=255 对应张开 0.04 m、ctrl=0 对应闭合。

`gripper.py` 在应用层又包了一层直观接口：`width_to_ctrl(width) = 255 × width / 0.08`
（注意应用层以双指总开口宽度 0–0.08 m 为口径，单指行程 0–0.04 m，两者差 2 倍）。

# 2. 物理仿真原理：MuJoCo 每一步在算什么

## 2.1 刚体动力学方程

MuJoCo 每个 `mj_step` 求解的是带约束的刚体动力学方程：

```
M(q) q̈ + c(q, q̇) + g(q) = τ + J_cᵀ f_c
```

- `M(q)`：广义质量矩阵（含连杆惯量和电机转子等效惯量）；
- `c(q,q̇)`：科氏力与离心力项（关节转得越快越大）；
- `g(q)`：重力项；
- `τ`：执行器输出的广义力；
- `J_cᵀ f_c`：接触约束通过雅可比转置映射成的等效力。

MuJoCo 把 `c + g` 合并存进 **`data.qfrc_bias`**（偏置力），这是后面重力补偿的关键。

## 2.2 数值积分：2 ms 步长与 implicitfast 积分器

模型实测 `opt.timestep = 0.002 s`，积分器为 **implicitfast**：

- **为什么需要小步长？** 物理仿真把连续时间微分方程离散成递推。步长太大时，
  刚体会在一个步长内「穿过」彼此，接触出现爆炸或穿透。2 ms 是机械臂接触仿真的常用折中。
- **implicitfast 在做什么？** 显式积分（Euler）把当前步的力直接乘步长更新速度，
  遇到大刚度接触和关节阻尼容易数值发散；隐式积分在更新速度时隐式考虑「下一步的阻尼/接触力」，
  稳定性高得多。`implicitfast` 是 MuJoCo 的简化隐式格式，稳定且开销小，适合带电机阻尼的机械臂。
- 模型还为每个关节配了 `armature="0.1"`（电机转子折算到关节的等效转动惯量）和
  `damping="1"`（关节黏性阻尼，单位 N·m·s/rad）。两者都会吸收高频振荡，是仿真稳定的重要来源；
  真实电机里转子惯量和摩擦阻尼本来就存在，所以这也是物理建模而非「作弊」。

## 2.3 执行器模型：PD 位置伺服的参数解读

七个手臂执行器是 `general` 类型，以 actuator1 为例：

```xml
<general name="actuator1" joint="joint1"
         gainprm="4500" biasprm="0 -4500 -450"
         ctrlrange="-2.8973 2.8973" forcerange="-87 87"/>
```

MuJoCo 的执行器输出 = gain 项 + bias 项：

```
τ = 4500·ctrl + (0·1 − 4500·q − 450·q̇)
  = 4500 (ctrl − q) − 450 q̇
      └── kp 比例项 ──┘   └ kd 微分项 ┘
```

这就是一个标准的 **PD 位置控制器**：`kp=4500 N·m/rad`，`kd=450 N·m·s/rad`。
你给的 `ctrl` 是**目标关节角**而不是力矩；执行器持续产生把实际角度 q 拉向目标的力矩。
`forcerange` 是力矩饱和上限（大关节 87 N·m、腕关节 12 N·m），模拟真实电机的最大出力。

**控制层级因此非常清晰**：

```
目标关节角 ctrl  →  PD 执行器  →  关节力矩 τ  →  刚体动力学积分  →  实际 qpos/qvel
```

`arm_control.py` 的 `command_arm_joint_positions()` 只写 `data.ctrl`，绝不直接改 `qpos`——
后者等于让机器人「瞬移」，绕过了动力学，不是真实控制。

## 2.4 重力（偏置）补偿：本项目最关键的控制细节

PD 控制器要同时对抗重力和驱动运动。但 PD 增益是按动态响应调的，重力这个「恒定扰动」
会让手臂在静止目标下依然下垂。工业机器人的标准解法是**前馈重力补偿**：把当前姿态下
抵消重力所需的力矩直接加进去。

本项目的实现（`arm_control.py`）：

```python
def apply_arm_bias_compensation(scene):
    # qfrc_bias = 重力项 + 科氏/离心项，随 qpos/qvel 每步变化
    scene.data.qfrc_applied[dof_addresses] = scene.data.qfrc_bias[dof_addresses]
```

每个物理步前，把 `qfrc_bias` 写入 `qfrc_applied`（外部施加力），于是 PD 只需处理
「目标与现状之差」，不必再扛重力。实测 home 姿态下各关节需要的补偿力矩：

```
[0.000, −29.06, 0.000, 21.75, 0.695, 2.011, 0.029]  N·m
```

joint2、joint4 承担整条手臂的重量（约 29、22 N·m），与它们靠近肩部、力臂长的直觉一致。

**对照实验（本仓库可复现）**：同样发送 home 位置命令，仿真 0.5 s：

| 条件 | 末端漂移 | 最大关节偏移 |
|---|---:|---:|
| 开启偏置补偿 | **0.00 mm** | 0.0000° |
| 关闭补偿 | **9.31 mm** | 0.3724° |

这解释了为什么 `motion.py` 的轨迹执行循环里，**每一个 `mj_step` 之前都必须调用一次**
补偿——姿态一变，`qfrc_bias` 就变，补偿值必须跟着更新。

> 与真机的联系：真实 Panda 的 libfranka 内部提供 `gravity` 和 `Coriolis` 力矩向量，
> 真机做 torque control 时同样要前馈这些项。本项目用 `qfrc_bias` 等价实现，
> 属于「理想模型补偿」——这也是 README 中强调结果仅限理想仿真的原因之一。

## 2.5 接触模型：方块为什么能被夹住而不滑掉

方块 geom 的定义：

```xml
<geom name="cube_geom" type="box" size="0.02 0.02 0.02" condim="4"
      friction="1.0 0.115 0.0001"/>
```

- **condim=4**：接触空间维数 = 1 个法向力 + 3 个切向摩擦分量
  （2 个滑动摩擦 + 1 个扭转摩擦）；
- **friction 三元组**：滑动摩擦系数 μ=1.0、扭转摩擦 0.115、滚动摩擦 0.0001；
- 方块质量 0.064 kg → 重力仅 **0.628 N**，很小，所以不大的夹持力就能靠摩擦拿住。

MuJoCo 的接触是**软接触**：两个 geom 接触时不会变成刚性钉死，而是通过
`solref`（接触响应时间）和 `solimp`（阻抗约束）参数生成一个随穿透深度增大的法向力，
本质是带阻尼的弹簧。手指 equality 约束上的 `solref="0.005 1"` 表示约束在约 5 ms 内收敛，
兼顾刚性与稳定。

每个物理步，引擎把当前所有接触点写入预分配的 `data.contact` 数组（有效项数为 `data.ncon`），
每项含两个 geom ID、接触位置、法向等原始信息——它**只记录当前一帧，不保存历史**。

# 3. 运动学：从关节角到末端位姿

## 3.1 位姿的三种数学描述

机器人学描述三维旋转有三种等价工具，本项目全部用到：

| 表示 | 维度 | 项目中的位置 | 特点 |
|---|---|---|---|
| 旋转矩阵 R | 3×3 | `kinematics.get_ee_rotation_matrix`、IK 目标姿态 | 9 个数含 6 个约束（正交且 det=+1），便于坐标变换 |
| 四元数 q | 4 (wxyz) | 方块 free joint 的 qpos[9:13]、`yaw_to_quaternion` | 无奇异、插值平滑，适合存储状态 |
| 旋转向量 rotvec | 3 | `rotations.rotation_error` 的输出 | 方向=转轴，模长=转角，适合做姿态误差 |

`rotations.py` 对旋转矩阵做了严格校验：`RᵀR=I`（正交）且 `det(R)=+1`（纯旋转，不含镜像）。

姿态误差的定义（`rotation_error`）：

```
R_rel = R_target · R_currentᵀ        （当前姿态到目标姿态的相对旋转，世界系）
e_o   = rotvec(R_rel)                （转轴 × 转角，3 维向量）
```

## 3.2 正运动学（FK）：关节角 → 末端位姿

正运动学回答：「给定 7 个关节角，末端在哪、朝哪？」数学上是一连串连杆坐标系变换的乘积：

```
T_0_ee(q) = T_01(q1) T_12(q2) … T_67(q7) T_7_ee
```

每个 `T` 是 4×4 齐次变换矩阵（旋转 + 平移）。本项目不需要手写这些矩阵——
MuJoCo 在每次 `mj_forward` / `mj_step` 后依据运动学树自动算出所有 body 和 site 的
世界坐标，`data.site("ee_center_site").xpos / .xmat` 就是 FK 结果。
`kinematics.py` 只负责把它包装成干净的读取接口。

## 3.3 雅可比矩阵：关节速度与末端速度的线性映射

雅可比 J 是 FK 的局部线性化，把关节速度映射成末端空间速度：

```
[v_e; ω_e] = J(q) q̇
```

`kinematics.get_ee_jacobian()` 通过 `mj_jacSite` 取出末端 site 的雅可比，
切成 **3×7 线速度雅可比 Jv** 和 **3×7 角速度雅可比 Jw**，堆叠后是 6×7。

实测 home 姿态下：`rank(Jv)=3`，`rank([Jv; Jw])=6`。这引出两个重要概念：

1. **奇异位形**：正常情况下 J 秩为 6（行满秩），末端可以向任意方向运动；
   当某些关节轴共线时 J 降秩，某些方向的末端运动变得不可实现或需要无穷大的关节速度，
   称为奇异。Panda 的冗余设计正是为了减少工作空间内的奇异。
2. **冗余零空间**：J 是 6×7 矩阵，零空间维数 = 7 − 6 = 1。
   即存在非零的关节速度向量 `q̇₀` 使 `J q̇₀ = 0`——末端不动、手臂自己调整肘部构型。
   这就是 7 轴臂冗余性的数学表达。

雅可比的另一个关键用途是把**笛卡尔空间误差**翻译成**关节更新量**，这正是 IK 的基础。

## 3.4 逆运动学（IK）：末端目标 → 关节角

IK 是 FK 的反问题：「想让末端到达位姿 (p*, R*)，7 个关节角该是多少？」
解析法对 7 轴 Panda 十分繁琐，本项目采用工业界常用的**数值迭代 IK——阻尼最小二乘
（Damped Least Squares, DLS / Levenberg–Marquardt 思路）**，实现在 `ik.py`。

### 3.4.1 推导

一阶近似下，末端误差与关节更新量满足 `e ≈ J Δq`。普通最小二乘解为
`Δq = J⁺ e`（J⁺ 为伪逆），但在奇异附近 J⁺ 数值爆炸，关节会甩出巨大步长。
DLS 给最小化目标加一个关节运动量惩罚：

```
min_Δq  ‖J Δq − e‖² + λ² ‖Δq‖²
```

解析解为：

```
Δq = Jᵀ (J Jᵀ + λ² I)⁻¹ e
```

对照 `damped_least_squares()`：它正是先解 `(JJᵀ + λ²I) y = e`，再返回 `Jᵀy`
（用 `np.linalg.solve` 而非显式求逆，数值更稳定）。阻尼 λ（默认 0.01–0.05）的作用：

- λ→0：退化为伪逆，收敛快但奇异附近不稳定；
- λ 大：轨迹平滑保守，但收敛变慢。这是速度与鲁棒性的折中。

### 3.4.2 迭代流程（`solve_pose_ik`）

```
重复最多 100 次:
  1. FK 读取当前末端位姿，算位置误差 e_p = p*−p 和姿态误差 e_o = rotvec(R* Rᵀ)
  2. 两者都低于容差（位置 1e-4 m，姿态 1e-3 rad）→ 成功退出
  3. 重新计算当前雅可比（姿态变了 J 就变，每轮必算）
  4. DLS 求 Δq，限制单关节单步 ≤ 0.1 rad，再裁剪到关节限位内
  5. 写 qpos，mj_forward 重算 FK（不推进仿真时间）
```

两个工程细节值得学习：

- **位姿 IK 把 Jv、Jw 垂直堆叠成 6×7**，位置误差和姿态误差拼成 6 维向量统一求解；
  步长限制采用「整体等比缩放」而非逐元素裁剪，避免破坏位置任务与姿态任务的协调方向。
- **规划与执行分离**（`plan_pose_target`）：IK 直接改 qpos 是纯运动学操作，若在真实
  控制场景里做会让机器人瞬移。代码新建一个独立 `planning_scene`（独立 MjData）跑 IK，
  只把求出的目标关节角带回控制场景，再由动力学轨迹真实运动过去。

实测对一个预抓取点做位姿 IK：**32 次迭代收敛，位置误差 1 µm、姿态误差 2e-6 rad**。
Day 14 的 50 目标批量评测中 IK 成功率 50/50，平均到达误差 0.027 mm。

# 4. 轨迹生成与运动控制

IK 只给出「终点的关节角」，但机器人不能瞬间跳到终点——需要一条随时间变化的**轨迹**。

## 4.1 关节空间线性插值

`linear_joint_trajectory()` 用 `np.linspace` 在起点和终点关节角之间等间距插值，
生成 N×7 的航点序列（MOVE_ABOVE 用 201 个航点）。每个航点是一时刻的 7 关节目标。

为什么在**关节空间**而不是笛卡尔空间直线插值？

- 关节空间插值保证每个中间点都是合法关节角，不会撞限位，计算简单；
- 代价是末端走的不是严格空间直线（本任务路径开阔、无障碍物，可接受）；
- `cartesian_trajectory.py` 另外提供了笛卡尔航点 + 逐点 IK 的方案，用于需要直线接近的场合。

## 4.2 轨迹执行与时间账

`execute_joint_trajectory()` 的节奏：

```
for 每个航点:
    写入 ctrl（PD 目标角）
    保持 10 个物理步（physics_steps_per_command=10）
        每步: 重力补偿 → mj_step
航点发完后再 settle 250 步保持最终目标，消除残余振动
```

时间账（2 ms/步）：MOVE_ABOVE = 201 × 10 × 2 ms + 250 × 2 ms = **4.52 s**，与实测完全吻合。
`settle_steps` 是工程上常见的「稳定段」：PD 伺服到达目标后仍有微小振荡，多保持半秒
让误差收敛到验收容差（位置 2 mm、姿态 1°）以内。

## 4.3 运动原语的验收思想

`move_end_effector_to()` 返回结构化的 `MotionResult`，按优先级给出失败原因：
状态非有限（NaN/Inf）→ 关节越限 → 位置容差 → 姿态容差 → 成功。
这种「每个动作都带客观验收和可追踪原因」的写法，是机器人工程区别于随手调脚本的关键。

# 5. 抓取任务的几何原理

## 5.1 自上而下抓取姿态与 yaw 对齐

`grasp_task.py` 定义基准抓取旋转矩阵：

```python
TOP_DOWN_GRASP_ROTATION = [[1,0,0],[0,-1,0],[0,0,-1]]
```

它的含义（矩阵的列就是末端坐标轴在世界系中的指向）：

- 末端局部 +z（接近轴）指向世界 **−z（垂直向下）**；
- 末端局部 +y（夹爪张合轴）指向世界 −y；
- 末端局部 +x 指向世界 +x。

方块只随机化绕世界 z 轴的偏航角 yaw（±30°，保持直立）。`top_down_grasp_rotation(yaw)`
再左乘一个绕 z 的旋转 `Rz(yaw)`，让夹爪水平轴**跟随方块边缘旋转**，保证两指平行于
方块两个对侧面，而接近方向始终竖直向下。

## 5.2 预抓取 / 抓取 / 抬升三点法

`generate_grasp_targets()` 依据方块中心位置生成三个笛卡尔目标：

| 目标 | 几何定义（实测 seed=42） | 作用 |
|---|---|---|
| pregrasp | 抓取点沿接近反方向退回 10 cm：(0.466, −0.007, **0.125**) | 先到上方安全位置，避免水平运动扫到方块 |
| grasp | 方块中心 + 5 mm z 偏置：(0.466, −0.007, **0.025**) | 垂直下降，让指尖包住方块两侧 |
| lift | 抓取点 + 世界 +z 8 cm：(0.466, −0.007, **0.105**) | 夹住后竖直抬起 |

「先上方悬停、再垂直接近、最后垂直抬起」是抓取规划的经典模式：把困难的接触运动
限制在单一竖直方向，水平方向只在安全高度移动，显著降低碰撞和不确定性。

# 6. 接触感知与抓取成功判定

## 6.1 从 data.contact 到任务语义

`contact.py` 解决的核心问题是：**引擎只给裸接触几何体 ID，如何回答「左指碰到方块了吗」？**

项目 Day 5 侦察发现指尖 geom 没有名字且每指由多个碰撞 geom 组成。解决方案是建立
**body → geom 集合**的映射层：

```
body 名称(left_finger/right_finger/cube) → body ID → 该 body 拥有的全部 geom ID 集合
每个接触项 (geom1, geom2) → 检查两个 ID 是否分别命中手指集合与方块集合
```

`ContactSensor.snapshot()` 每步统计左指–方块、右指–方块、方块–地面三类接触条数。
注意 geom 顺序不固定，所以两个方向都要判断。

## 6.2 单帧接触 ≠ 稳定抓取：时间滤波

单帧双侧接触可能只是擦碰瞬间。`BilateralContactTracker` 引入**持续性判据**：
只有双侧接触**连续**保持 ≥ 0.1 s（50 个物理步）才计为持久接触，中途断一帧计数清零。
这本质是对二值信号做时间滤波，滤除毛刺。

## 6.3 抓取力学：摩擦握持的力平衡

方块不掉落的物理条件：手指摩擦力之和 ≥ 方块重力。

```
方块重力: m g = 0.064 × 9.81 ≈ 0.628 N
每指需提供摩擦: ≈ 0.314 N
摩擦系数 μ = 1.0 → 所需总法向夹持力 ≥ 0.628 N
```

实测一次成功抓取后：左右指各 16 个接触点（共 32 个，指尖由多个 box geom 构成所致），
每个接触点法向力约 0.06 N，总法向力约 1.9 N，裕量充足；方块–地面接触为 0（已离地）。
注意文档中反复强调的：**接触条目数不是接触力**，力要通过 `mj_contactForce` 读取。

## 6.4 GraspMonitor 的多重判据

`GraspMonitor` 把四类信息组合成两级语义（`contact.py`）：

- **grasp_candidate（允许抬升）** = 持久双侧接触 **且** 夹爪宽度落在 [0.005, 0.075] m
  （防止没夹住或空夹）；
- **grasp_success（最终成功）** = candidate **且** 方块离地 ≥ 5 cm
  **且** 线速度 ≤ 0.02 m/s、角速度 ≤ 0.2 rad/s（夹持稳定不晃动）**且** 不接触地面。

`reason` 属性按优先级输出未满足的首项原因（no_bilateral_contact / cube_not_lifted /
cube_not_stable…），让失败可诊断。监测器只读不写，严格遵循「观测与控制分离」。

# 7. 任务层：有限状态机组织完整抓取

`pick_controller.py` 用 9 个状态的**有限状态机（FSM）**把上述能力串成完整任务。
FSM 是机器人任务编排的主流模式：每个状态做一件事，转移条件明确，失败可定位到具体阶段。

| 状态 | 动作 | 转移/失败条件 |
|---|---|---|
| RESET | 回 home、采样方块、动力学落稳 | 落不稳 → FAILED(cube_not_settled) |
| MOVE_ABOVE | IK + 关节轨迹到预抓取点 | IK 失败/越限/容差不达标 → FAILED |
| APPROACH | 保持抓取姿态垂直下降到 grasp 点 | 同上 |
| CLOSE_GRIPPER | 发闭合命令，最多等 1 s，监测器逐步更新 | 形成持久双侧接触即提前结束 |
| VERIFY_CONTACT | **不发任何动作**，只读监测器裁决 | 非 candidate → FAILED（接触故障） |
| LIFT | 保持闭合，运动到 lift 点，全程监测 | 运动失败或方块没离地 → FAILED |
| CHECK_SUCCESS | 原地保持，要求连续 0.5 s 全部满足成功判据 | 累计中断则清零重来，超时失败 |
| DONE / FAILED | 输出含每阶段记录的 PickResult | — |

两个设计精髓：

1. **VERIFY_CONTACT 独立成态**：它不执行动作，只做决策。README 中的失败演示视频
   故意把夹爪闭合限制为一个物理步，FSM 就会在这个状态正确拒绝抓取——
   说明状态机具备真实的故障检出能力，而不是无脑走流程。
2. **CHECK_SUCCESS 用「连续成功帧」而非单帧判定**：与接触持续性同理，
   防止方块被瞬间抬离地面又滑落被误判成功。Week 3 验收要求最小保持 0.5 s、最小抬升 7.7 cm。

# 8. 可复现实验方法学

## 8.1 随机化与确定性

`cube_reset.py` 的设计体现了严谨的实验纪律：

- 用 `np.random.default_rng(seed)` 创建**局部随机数生成器**，不污染 NumPy 全局随机状态，
  同 seed 永远产生同一方块位姿（x∈[0.42,0.48] m，y∈[−0.06,0.06] m，yaw∈±30°）；
- 方块先放在 5 cm 高度，再通过**真实动力学仿真自然落稳**（`settle_cube`），
  而不是直接摆在地面——避免初始穿透和不接触；
- `reset_to_home()` 是**绝对写入**而非增量调整：直接覆盖 qpos/qvel/ctrl 再 `mj_forward`，
  天然幂等，连 reset 10 次结果逐位相同；
- reset 后自动断言关节限位与有限性（无 NaN/Inf），让非法状态当场暴露。

## 8.2 验收指标体系

项目的三层基准评测：

| 评测 | 脚本 | 指标 | 实测结果 |
|---|---|---|---|
| 到达 | `day14/evaluate_reach.py` | 50 个固定目标 IK/到达成功率、误差 | 50/50，平均误差 0.027 mm |
| 脚本抓取 | `day21/week3_acceptance.py` | 20 个随机 seed 成功率、抬升、保持 | **20/20，最小抬升 7.73 cm，最小保持 0.5 s** |
| 学习到达 | Day 27 held-out 评测 | 10 个未见 seed 的末端误差 | SAC 86 mm vs 随机 789 mm |

每次评测都落盘 CSV 逐样本数据，并明确声明适用边界（固定 seed 范围、捆绑模型、理想仿真），
不做超出实验支持范围的泛化宣称——这是科研型项目的重要素养。

# 9. 学习式路线：Gymnasium 接口与强化学习

脚本策略能 100% 成功，但它依赖已知方块位置和手工编排。项目 Week 4 进一步搭建了
**强化学习环境**，让策略可以从交互中学习。

## 9.1 观测、动作、奖励、终止

**观测向量（29 维，`panda_pick_task.py` 具名切片）**：

```
[0:7]   手臂 7 关节角
[7:14]  手臂 7 关节速度
[14]    夹爪当前宽度
[15:18] 末端位置 xyz
[18:21] 方块位置 xyz
[21:23] 方块 yaw 的 sin/cos（角度的连续编码，避免 ±π 跳变）
[23:26] 方块线速度
[26:29] 方块角速度
```

**动作空间（`continuous_env.py`，7 维连续 ∈[−1,1]）**：3 维位置增量（每步最大 2 mm）
＋ 3 维旋转增量（每步最大 2°，用旋转向量→旋转矩阵实现）＋ 1 维夹爪宽度增量。
`action_mapping.py` 先裁剪再映射为笛卡尔目标，经 IK 转关节目标后交给 PD 执行器，
每个 env step 内部跑 10 个物理步（frame_skip=10 → 20 ms 决策周期）。

**奖励塑形（`rewards.py`，分项可追踪）**：

- 位置/姿态误差的**下降量**给奖励（progress reward，引导逼近而非只看终点）；
- 首次形成持久双侧接触给一次性 bonus（避免重复领奖）；
- 方块抬升高度的增加量给奖励；
- 成功给 +5 大奖；动作能量（均方）给小惩罚，鼓励平滑运动。

**终止语义（`termination.py`）**严格区分 Gymnasium 两个布尔量：

- `terminated=True`：任务自然结束（成功或不可恢复失败）；
- `truncated=True`：达到 500 步上限被外部截断，**不代表失败**，bootstrap 处理方式不同。

## 9.2 脚本策略与学习策略的关系

仓库架构让两条路线共用同一套 MuJoCo 场景与控制组件：

```
脚本 FSM ──→ 运动原语 ──→ IK ──→ 关节位置控制 ──→ MuJoCo
SAC 策略 ──→ 笛卡尔增量动作 ──→ IK ──→ 关节位置控制 ──→ MuJoCo
```

SAC（Soft Actor-Critic，最大熵强化学习算法）在 100k 步训练后把平均到达误差从
随机策略的 789 mm 降到 86 mm，证明学到了有用的趋近行为，但尚未达到成功阈值，
且 Week 4 实验刻意只做 Reach（夹爪保持张开），不宣称掌握抓取。
这种诚实的基线对比和局限性说明，比一个夸大的「端到端成功」更有工程价值。

# 10. Sim-to-Real：仿真与真机的差距清单

本项目所有结果都在理想仿真中取得。迁移到真实 Panda 时，下列简化会逐个变成挑战：

| 仿真中的理想化 | 真机现实 | 应对方向 |
|---|---|---|
| 直接读取精确 qpos / 方块位置 | 需要编码器、相机感知与标定，含噪声和延迟 | 视觉伺服、状态估计、噪声建模 |
| `qfrc_bias` 完美重力补偿 | 模型参数有误差，存在未建模摩擦 | 动力学历辨识、自适应控制 |
| PD 增益固定且瞬时响应 | 电机循环周期 1 kHz、通信延迟、力矩纹波 | 实时控制、阻抗控制 |
| 摩擦系数给定（μ=1.0） | 真实摩擦随材质/油污/温度变化 | 力传感器反馈、触觉感知 |
| 网格接触稳定无抖动 | 真实接触有冲击、振动、磨损 | 柔性指尖、力控闭合 |
| 方块位姿完全已知 | 需要物体检测与 6D 位姿估计 | 点云/Dex-Net 类抓取规划 |
| 无人为扰动、无建模误差 | 标定误差、齿轮背隙、线缆拖拽 | 域随机化、鲁棒控制、Sim2Real 微调 |

仓库里已经具备一项面向 Sim2Real 的正确实践：**域随机化的雏形**
（方块位置/朝向随机化），RL 训练时扩大随机范围是缩小现实差距的主流手段之一。
